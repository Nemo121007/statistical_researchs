# Проверка изменённых модулей app/

Аргументы (в Claude Code — `$ARGUMENTS`, в OpenCode — из команды или запроса пользователя): модули (`app.evaluation.geospatial_metrics`) или файлы (`app/evaluation/geospatial_metrics.py`).
Если аргументов нет — взять файлы `app/`, изменённые в текущем задании (по последнему блоку `change.log`
и правкам этой сессии). Проверять только их, не весь пакет.

Все команды — из корня проекта, интерпретатор `.venv/bin/python`.

## Шаги

1. Импорт каждого модуля:
   `.venv/bin/python -c "import <модуль>"` — ожидается пустой вывод и код 0.
2. Pylint по файлам одним вызовом:
   `.venv/bin/pylint <файлы> --score=n`.
   - Замечания, кроме R09xx, — исправить в рамках задания (правило «Согласование действий» в `AGENTS.md`)
     и повторить шаг.
   - R09xx (too-many-*) — не исправлять, только перечислить в отчёте.
3. Демо: для файлов, где есть `if __name__ == "__main__":`, —
   `MPLBACKEND=Agg .venv/bin/python -W ignore -m <модуль>`; ожидается код 0. Числа демо сравнить с прежними,
   если они известны из этой сессии.
4. Переводы строк: `file <файлы>` — у `app/*.py` должно быть `with CRLF line terminators`, без `CRLF, LF`.

## Отчёт

Коротко, по пунктам: какие модули проверены; импорт; pylint (что исправлено, какие R09xx остались);
демо (код выхода, ключевые числа); CRLF. При провале — точная ошибка и предложение исправления.
