# Работа с отчётом

Аргументы (в Claude Code — `$ARGUMENTS`, в OpenCode — из команды или запроса пользователя): что нужно сделать
с отчётом.

Отчёт — черновик научной работы, собирается пользователем удалённо (LaTeX на этой машине нет). Правка
`report/Отчёт.tex` — только после явного подтверждения пользователя (`AGENTS.md`, «Запреты»).

## Порядок

0. Открыть `report/rewrite_plan.md` — план переписывания отчёта по этапам. Если задача относится к одному
   из пунктов плана — работать по нему и после выполнения отметить пункт `[x]`; новые найденные расхождения
   добавлять в план, а не исправлять попутно.
1. Прочитать нужный фрагмент отчёта и `report/glossary.md`.
2. Сверить содержание с источником истины: формулы и порядок расчёта — с `app/` и `notebooks/example_model.ipynb`,
   числа — со снимком результатов блокнота. Расхождения не исправлять молча: перечислить пользователю.
3. Согласовать с пользователем текст правки (если правка содержательная, а не механическая).
4. Внести правку по правилам стиля ниже.
5. Глоссарий: каждое новое или изменённое обозначение и термин — в `report/glossary.md` в этом же задании.
   Если отчёт использует обозначение, которого нет в глоссарии, — добавить или спросить.
6. Проверить LaTeX без сборки: парность `\begin{…}`/`\end{…}` по каждому окружению
   (`grep -c`), отсутствие `$$` в новых фрагментах, отсутствие запретных обозначений (см. ниже).
7. Запись в `change.log`: блок `## <дата> — <задание>`, строки по файлам.

## Правила стиля

Жанр и тон:

- Черновик научной работы; соответствие ГОСТ не требуется.
- Научный стиль во всех разделах, включая разбор результатов: безличные конструкции, без разговорных
  оборотов («ломает», «имеет смысл», «в ближайший заход»); смысл, числа и структура выводов сохраняются.
- Черновые пометки — только командой `\todo{…}` (определена в преамбуле, выделяется цветом в PDF),
  не курсивом и не `%`-комментарием.

Структура:

- Все заголовки нумеруются: `\section`, `\subsection`, `\subsubsection`, без звёздочек; номера вручную
  в тексте заголовков не пишутся.
- Подзаголовки внутри описания модели — `\paragraph{Формализация}`, `\paragraph{Обучение и выбор порога}`;
  не `\textbf{…}:\\`.

Типографика:

- Тире — только `---`, не символ «—».
- Выключные формулы — `\[ … \]` или `equation*` / `align*`; `$$ … $$` не использовать.
- Абзацы — пустой строкой; ручной перенос `\\` только в таблицах, формулах и окружениях, где он нужен.

Числа и единицы:

- Десятичный разделитель — точка, в тексте и в таблицах (`0.845`, не `0{,}845`); разряды больших чисел — `\,`.
- Секунды — «с», не «сек.».
- В тексте доли и метрики классификации — 3 знака после точки (`0.845`); расстояния — с единицами и разумным
  округлением (`73.2 км`, `2.76 млн м`). В таблицах точность — как в выводе блокнота.

Обозначения и термины:

- Обозначения — строго по `report/glossary.md`: плоские координаты $o_i$ (восток) и $n_i$ (север),
  $y_i$ — только метка класса, ускорение — $a^{\mathrm{acc}}_i$.
- Термины — по разделу «Термины» глоссария: русский термин, при первом упоминании английский в скобках.
- Сценарии — «сценарий $\rho=0.6$», «сценарий $\rho=0.8$», не df1/df2; имена констант блокнота в тексте
  не упоминаются.
- Подписи столбцов таблиц — на русском по глоссарию; принятые сокращения (RMSE, DL, F1, MCC) остаются.
  Длинные группы столбцов — двухуровневой шапкой (например, «Задержка, с»: мед., ср., p95, макс.).
