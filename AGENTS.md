# statistical_researchs — инструкции для агента

Исследование: детекция аномалий в GPS-телеметрии судов. Метка 0 — anomaly
(положительный класс), значение больше нуля — move.

## Рабочая директория

- Всегда работай с основными файлами проекта в, а не с копиями в отдельных worktree OpenCode.
- Если текущая сессия открыта в worktree, правки всё равно вноси в основной каталог и коммить туда, чтобы изменения сразу появлялись в сторонней IDE.

## Коммиты

- Коммитить только по явной команде пользователя. Без такой команды изменения остаются в рабочем дереве.
- В сообщении коммита указывать содержимое изменений: что сделано, какие файлы,
  разделы, функции или поведение затронуты. Формулировка должна быть
  понятной без открытия diff, а не «Фиксация файлов».
- Стиль оформления коммита: название измененного файла/модуля + ":" + описание и содержимое изменений на русском языке

## Журнал изменений

- Рабочая копия проекта без git: изменения фиксируются в `change.log` в корне.
- Каждое задание — блок в конце файла с заголовком `## <дата> — <краткое название задания>`.
  Под заголовком — записи в формате сообщения коммита: название изменённого файла/модуля + ":" +
  описание и содержимое изменений на русском языке, по строке на файл.
- Записи не удалять и не переписывать: `change.log` очищается при реальном коммите.

## Инструменты

- Читать и искать можно любым инструментом, предназначенным для чтения: встроенными
  (`read`, `grep`, `glob`) или shell-командами (`grep`, `sed`, `head`, `jq`), если встроенного нет
  или файл не читается целиком (например, большой `.ipynb`).
- Не создавать временные Python-файлы и не писать `python -c` / `node -e` ради чтения и разбора файлов.
- Ячейки блокнотов править специальным инструментом для блокнотов, если он есть; иначе — `edit`.
- Большие блокноты (`example_model.ipynb`, `kalman_change_points.ipynb`) не открываются целиком
  ни чтением, ни инструментом для блокнотов. Порядок правки: найти строки через `grep -n`,
  посмотреть их через `sed -n`, заменить через `sed -i` по номерам строк, затем проверить, что
  файл остался корректным JSON: `python -m json.tool <файл> > /dev/null`.
- Для прочих правок — `edit` (или `write` для полного перезаписывания).
- `shell` — для запуска скриптов и модулей, `pylint`, работы с окружением.

## Стиль кода

Правила обязательны для нового и изменённого кода; существующий код массово не переделывать.

- Комментарии и докстринги — на русском, докстринги в стиле Google, строка до 120 символов.
- Новый код сразу писать в стиле `black` (настройки — `pyproject.toml`).
- В каждом модуле — строка документации модуля на русском и `from __future__ import annotations`.

Типы:

- Аннотации обязательны у параметров и возвращаемого значения публичных функций и методов.
- Коллекции — встроенные generic-типы (`dict`, `list`, `tuple`); nullable — только `Optional[X]`, не `X | None`.

Докстринги:

- Шаблон Google: краткое описание, пустая строка, затем `Args`, `Returns`, `Raises`. Секции `Returns`
  и `Raises` — только если функция что-то возвращает или выбрасывает. Тип в `Returns` не повторять:
  он есть в аннотации. Единицы измерения — в описании. Короткой приватной функции хватает одной строки.
- Имена аргументов функции в тексте докстринга выделять двойными обратными кавычками (``xy``),
  чтобы PyCharm их подсвечивал.

  ```python
  def segment_distances_m(lat: np.ndarray, lon: np.ndarray) -> np.ndarray:
      """Длины звеньев ломаной по геодезической, м.

      Args:
          lat: Широты, градусы; длина как у ``lon``.
          lon: Долготы, градусы.

      Returns:
          Массив длины N-1.

      Raises:
          ValueError: Разная длина или координаты вне WGS-84.
      """
  ```

Именование:

- Физические величины — с суффиксом единиц: `_m`, `_s`, `_mps`, `_deg`, `_rad`.
- Приватное — одно подчёркивание; двойное (name mangling) не использовать.
- Магические числа — в именованные константы.

Поведение и данные:

- Публичные функции проверяют вход и выбрасывают `ValueError` с сообщением на русском.
  Широкий `except Exception` не использовать.
- Соглашения о данных: метка 0 — anomaly; координаты — градусы WGS-84 или метры ENU; время
  в расчётах — секунды. Новый код не вводит своих кодировок.
- Ряды и маски — векторы numpy с явным типом: значения — `np.float64`, маски — `bool`.
- Расчёты по точкам ряда векторизовать через numpy вместо циклов Python, если это не меняет логику.

Оформление:

- Комментарии объясняют «почему», а не «что». Без закомментированного кода и разделителей вида `# -----`.
- Демо в `__main__` — короткое, на синтетическом ряду, без файлов на диске.
- `black` и `isort` не прогонять по файлам целиком без команды: правка утонет в переформатировании.
- Файлы `app/*.py` — с переводами строк CRLF. При правке через shell сохранять CRLF, иначе pylint
  выдаёт `mixed-line-endings`.

## Эксперименты

- Блокноты запускаются с рабочей директорией `notebooks/`, данные — тестовый
  файл `../data/test.csv`.
- `data/test.csv` — синтетический ряд только для проверки запускаемости: выводы о моделях по нему
  не делать. При необходимости — перегенерировать и перезаписать файл, генератор не сохранять.
- Прогон блокнота — в памяти через IPython `InteractiveShell`, без сохранения выходов в файл,
  чтобы не затирать результаты прогонов на реальных данных. Корень проекта — в `sys.path`,
  `MPLBACKEND=Agg`, переключение GUI отключено (`shell.enable_gui = lambda gui=None: None`),
  иначе `%matplotlib inline` обрывает ячейку импортов. Сохранять выходы — только по команде.
  Готовый скрипт: `.claude/skills/run-notebook/run_notebook.py` (порядок запуска — в `SKILL.md` рядом).
- Если правка кода меняет то, что описано в markdown той же модели, — обновить описание.
  Записи о результатах прошлых прогонов не трогать.
- Новый детектор повторяет структуру блока ARIMA в `example_model.ipynb`.
- Порог: максимум MCC на train, затем полоса `MCC_BAND`, затем минимальный
  операционный distance loss; на test переносится тот же порог без подгонки.

## Проверка

- Тестов и CI нет. После правки модулей `app.*` — импорт именно изменённых модулей,
  `pylint` по изменённым файлам и `python -m <модуль>`, если в нём есть демо в `__main__`.
- `app.viz` не импортировать на уровне модулей `app.evaluation`: это замыкает цикл
  `app.viz` → `app.evaluation` → `app.viz`. Для демо — импорт внутри `__main__`.
